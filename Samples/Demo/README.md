# Demo data

Synthetic logs + rules used for the README screenshots (`docs/screenshots/`) and for trying
FindNeedle without hunting for real logs. **Everything here is fake** — made-up services,
users, and IP addresses; no real data.

## `logs/` — a multi-service trace

Three fake service logs (~12,500 lines total) that look like a small distributed system:
`auth-frontend.log`, `orders-backend.log`, `edge-proxy.log`. They contain a realistic mix of
levels (INFO/DEBUG/WARN/ERROR) with searchable events — try `TIMEOUT`, or filter to **Error**.

Generated by [`gen_logs.py`](gen_logs.py) with a fixed seed, so re-running produces
byte-identical files — that's why the logs are committed: the screenshots stay reproducible.

```
python gen_logs.py     # rewrites ./logs/*.log
```

Load the `logs/` folder in FindNeedle (Open Folder, or `FindNeedleUX.exe <path-to>/logs`) to
reproduce the result-viewer, search, and level-filter screenshots.

## `uml/` — reconstruct a request flow as a diagram

A tiny curated trace (`checkout-trace.log`, one `/checkout` request) plus RuleDSL rules that turn
it into a Mermaid **sequence diagram** — the "diagram your logs" feature. It shows the two-layer
UML format:

- **`checkout-flow-wrapper.rules.json`** — a unified *output* rule whose `uml` action references a
  `rulesFile`. This is what you load as the rules file for a search.
- **`checkout-flow.rules.json`** — the flat UML definition (`participants` + `rules` + `action`)
  referenced by the wrapper. The app resolves `rulesFile` by name relative to the working directory
  or by searching the app folder, so keep the two files together (or run from this folder).

To generate the diagram: open `checkout-trace.log` with `checkout-flow-wrapper.rules.json` as the
rules file, then **Run & Results → Processor Output → Generate** (needs Mermaid or PlantUML
installed — see Tools → Diagram Tools). The result is the checkout sequence:
`Client → RequestHandler → AuthService → CacheLayer → DbPool`, including the DB timeout + retry.
